Acceptance matrix, re-run AFTER the two liveness fixes.
Compare against docs/results/acceptance-matrix.txt (run 20260921T183303-1e23), which is NOT replaced.

What changed in the engine between the two runs:
  1. A lost race for an event sequence number no longer retires a workflow or
     activity worker. The task is released and the loop continues. (Both
     workers had the defect; both are fixed.)
  2. WorkerPool.Start now tops a shard back up to full worker strength, for
     shards the lease manager still reports as owned.
  3. A running activity renews its task claim (taskq Queue.Extend) every third
     of TASK_LOCK, so an activity longer than the 30s claim is no longer handed
     to a second worker while it is still running.

These are liveness fixes. Nothing the engine refuses to do changed, so every
safety row here should read exactly as it did before. The point of this file is
to show that, not to assert it.

This run reads a LARGER event log than the published one: 8,885 runs here
against 6,770 there, because the duplicate and scaling re-runs went first on
purpose. (A first attempt at this file, kept as
acceptance-matrix-after-liveness-fix-pre-load.txt, ran before the load and
found only 7 runs in the log — it had been emptied at some earlier point, which
is worth knowing but makes that run weak evidence.)
