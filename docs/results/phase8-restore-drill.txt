WHAT THIS DOES NOT SHOW:
  * tasks=0 and activity_intents=0 in the dump. A dump taken while work is
    IN FLIGHT would capture executions with no driving task row, so after a
    restore those runs are stranded until the reconciler adopts them. That
    path was not exercised here.
  * restoring to an EARLIER point rewinds the journal behind external
    reality: activities whose effects already happened would replay and be
    re-invoked. They carry the SAME journaled dedup key, so a recipient that
    honours the key absorbs them - the same conditional guarantee as Phase 7,
    now also load-bearing for disaster recovery.
  * archive_mode=off, so there is NO point-in-time recovery at all.
