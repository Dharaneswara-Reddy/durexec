 A real, complete run of the twelve deterministic comparators over all three
 corpora, with the real encoder. Nothing in it is estimated and nothing was
 deleted. It is NOT the result, because of what it embedded.

 The engine has two ways of turning an activity's input into the sentence it
 embeds and hands to a field extractor:

   the activity's own renderer   app/agent registers toolCallIntent for its
                                 tool calls, which returns the bare canonical
                                 argument sentence: "blr to del friday
                                 morning". cmd/engined wires exactly this into
                                 Checker.RenderIntent, so it is what the
                                 engine journals in production.

   the checker's fallback        semantic.IntentText, used when no renderer is
                                 registered: the whole envelope,
                                 BookFlight({"args":"blr to del friday
                                 morning","tool":"BookFlight"}).

 This run used the FALLBACK, for every arm. So did cmd/experiment, and so did
 every figure in docs/results/semantic-experiment-minilm.txt and
 semantic-experiment-hybrid-minilm.txt.

 The envelope is nearly identical across every call of one activity type —
 the type name appears twice, the JSON keys always — so most of what gets
 embedded is constant and every cosine is pulled upwards. Measured here, the
 pure-semantic comparator caught 45 of 45 genuine rewordings from the live
 planner, where the same comparator over the bare sentences in
 docs/results/rephrase-live-model.txt caught 34 of 45. That gap is the
 scaffolding, not the model.

 The corrected run, using the rendering the engine actually journals, is
 field-extractors.txt and .csv. It carries one arm,
 "semantic-envelope-rendering", that reproduces this rendering so the two can
 be compared in one table.

 This file is kept as the evidence for that comparison, and as a record that
 the published semantic-experiment figures measure a rendering the engine does
 not use for the activities the experiment is about.

 DUPLICATE prevents a repeat. With it on, an uncertain verdict holds the activity
 for a person. It is one line of configuration and no extraction at all, so it is
 the cheapest thing in this file and has to be measured against the rest.

===========================================================================
 WHAT WAS CHANGED AFTER SEEING SCORES, AND WHY
===========================================================================

 An earlier run of this harness, on this corpus, with this embedder, is kept at
 docs/results/field-extractors-before-changes.txt and .csv. It was measured the
 same way; nothing was deleted. Four things changed between it and this file,
 and none of them was a special case added for a pair that had failed.

 1. A BUG, found by reading the extracted signatures rather than the scores.
    The engine's intent text is `ActivityType({"args":"...","tool":"ActivityType"})`,
    so the activity's own name appears inside the JSON as well as in front of it.
    The copy inside the JSON is not sentence-initial, so the generic extractor's
    proper-noun rule read it as a deciding value on EVERY call of that activity.
    Every intent was therefore "recognised" on the strength of its own type name —
    the one token incapable of telling two calls of it apart. Extracted values are
    now filtered against the activity name and the envelope's keys.

 2. VALUES OF ONE FIELD ARE NOW SORTED instead of kept in the order they were
    said. "A P1 ticket on TCK-219" and "TCK-219 as P1" are one ticket, and order of
    appearance is a property of the sentence rather than of the action. The price
    is stated rather than hidden: with the values sorted this extractor cannot tell
    an outbound booking from its return leg, and the flight domain's
    reversed-direction negatives below are what that costs.

 3. THE NEUTRAL GATE TOLERATES A SUBSET. The same reasoning that makes an absent
    FIELD neutral applies one level down: if one side's values for a field are
    contained in the other's, that side said less, not something else. Two
    disjoint value sets still close the gate. The STRICT rule is untouched, because
    it is the rule every published hybrid figure was measured under.

 4. TWO NEW DECISION MODES, both added because the first run showed the leftover
    free text destroying the comparator rather than helping it. The gate passed
    the great majority of genuine duplicates and the remainder threshold then
    rejected almost all of them, for a reason that is obvious in hindsight: a
    remainder is what is LEFT once the values are removed, so it is short, and a
    threshold calibrated on whole sentences is wrong for it.
      gatedecides  the remainder may only downgrade to ESCALATE, never to DISTINCT
      gateonly     the remainder is never embedded and never consulted
    Both are off by default in the engine, and both appear as their own arms above
    rather than replacing anything.

 WHAT WAS NOT DONE. No per-pair special case, no vocabulary entry, no threshold
 chosen from the sweep in this file. The hand-written extractor was not touched
 at all: it is the baseline, and editing it would have destroyed the comparison.

    not because a person confirmed a user would consider them interchangeable.
    Where that assumption is wrong, the accuracy here is wrong by the same amount.
    No inter-annotator agreement exists because no annotation exists.
  - That the designed negatives resemble the mistakes a real planner makes. They
    were written to move one deciding field at a time, which is a modelling
    choice; the live corpus has the real wordings but no negatives at all.
  - That the hand-written extractor's figures on the flight corpus are inflated.
    Its vocabulary was written by reading that corpus, which is selection on the
    test set and cannot be undone by measuring more carefully.

 NOT MEASURED, AND NOT TO BE INFERRED FROM THIS FILE
  - Whether a person agrees with any ESCALATE verdict. The blocking policy's
    catch rate assumes a human adjudicates correctly, and nothing here asked one.
  - End-to-end engine behaviour. The comparators are the engine's, but these
    pairs were scored in a harness with an in-memory candidate store, not against

  - Any other embedding model, and for the LLM arm any other extraction model,

  - The determinism of the LLM arm across runs. It is a network call to a sampled
    model at temperature 0, cached here so the run is reproducible from the cache;

    it survivable in the engine is that the VERDICT is journaled once and replay

    the deterministic extractors' explanations can.
