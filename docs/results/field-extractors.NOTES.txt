Companion notes for docs/results/field-extractors.csv
================================================================================

WHAT THIS FILE IS
  One row per COMPARATOR per PAIR, written and flushed as each row was
  measured. It is the raw data behind docs/results/field-extractors.txt, and
  every figure in that file is a count or a rate over these rows. Nothing in
  the report is accumulated in memory while measuring: the report is built by
  reading this file back, which is why a run killed part way still produces a
  valid partial report.

WHAT WAS BEING ASKED
  The engine's hybrid duplicate check needs the DECIDING FIELDS of an action —
  the values that make it a different action. It had exactly one way to find
  them, a hand-written flight vocabulary
  (internal/idem/semantic/itinerary.go), and the live crash-and-rephrase run
  measured that reading 100% of flight intents and 0% of four other domains'.
  This run scores three ways of finding them, on the same pairs, with the
  engine's own comparator code:

    itinerary  the hand-written flight vocabulary — the baseline
    generic    value SHAPES, no vocabulary, no network, deterministic
               (internal/idem/semantic/generic.go)
    llm        one model call per intent returning the deciding values as JSON
               (app/agent/llm/fields.go), temperature 0

  and against the engine's two existing comparators: its exact byte key, and
  the shipped pure-semantic path.

HOW TO RESUME AN INTERRUPTED RUN
  Rows already present are skipped, keyed by comparator|corpus|pair_id, so
  re-running the exact same command continues where it stopped. The exact
  command is in the header of field-extractors.txt, under "resume".

HOW TO REGENERATE THE REPORT WITHOUT MEASURING ANYTHING
  Add -report-only. It reads this CSV and recomputes every table from it. No
  API key, no embedding service and no model are needed.

    go run ./cmd/fieldeval -report-only \
      -csv=docs/results/field-extractors.csv -txt=<where to write the report>

THE COMPARATOR NAMES
  exact                     the engine's own canonical idempotency key
  semantic                  the shipped pure-semantic path, no gate
  hybrid-<extractor>-<gate>[-<decision>][-cased]

    <extractor>  itinerary | generic | llm
    <gate>       strict   a deciding field present on one side and absent on
                          the other IS a difference. This is the rule every
                          published hybrid figure was measured under.
                 neutral  only two values that are both present and genuinely
                          contradict close the gate. Absence is no
                          information. Requires min_agreeing fields to agree
                          before it will pass a pair.
    <decision>   (none)       the comparator as first built: the leftover free
                              text can veto, so an agreeing field set still
                              ends in DISTINCT if the remainder is not similar
                              enough.
                 gatedecides  the gate's answer stands and the remainder can
                              only downgrade to ESCALATE, never to DISTINCT.
                 gateonly     the similarity half is removed entirely. The
                              remainder is never embedded and never consulted.
    -cased       the intent text keeps its capitals. app/agent lowercases every
                 tool call through agent.CanonicalIntent, which destroys the
                 only signal the generic extractor's proper-noun rule has, so
                 both are measured. A -cased row is NOT the engine's current
                 path and is marked as such everywhere it appears.

THE COLUMNS
  corpus                  multidomain-300 | flight-213 | rephrase-live
  domain                  the kind of action: flight, payment, refund, meeting,
                          message, order, provisioning, ticket, subscription,
                          shipment
  activity                the activity type the pair was scheduled under
  pair_id                 stable across runs; part of the resume key
  category                paraphrase | near-miss | contrast | surface |
                          fixture | live-reword
  hard                    the two sides share at least half their words, so
                          telling them apart takes more than noticing they are
                          about different things. MEASURED from the words, not
                          declared by the author.
  truth                   DUPLICATE or DISTINCT, the ground-truth label
  comparator, extractor, gate_mode, min_agreeing, case_preserved, gate_decides
                          which comparator produced this row
  exact_hit               the byte-key baseline's answer. Separate from
                          similarity because the exact baseline measures no
                          similarity at all.
  recognised_a/_b         whether the extractor could read that side's intent.
                          When either is false the comparator FELL BACK to the
                          pure-semantic path and the verdict is that path's.
  gated                   a deciding field differed, so no threshold could have
                          made this pair a duplicate
  gate_field              which field closed the gate, with both values in
                          signature_a and signature_b
  agreeing_fields         how many deciding fields both sides stated without
                          contradicting. The gate's only positive evidence.
  similarity              the cosine the checker reported: over the whole
                          intent on the pure path, over the free-text remainder
                          on a hybrid path, 1.0 on a gateonly pass (nothing was
                          measured), 0 when the gate answered without measuring
  similarity_free_text    the free-text cosine from Compare
  model_used              whether answering actually required an embedding.
                          WHERE THIS IS FALSE THROUGHOUT AN ARM, THAT ARM IS
                          MEASURING EXACT MATCHING OVER EXTRACTED VALUES AND
                          NOT SEMANTIC SIMILARITY.
  fallback                the verdict was reached without the model because the
                          model was unavailable, so a similarity of zero is an
                          absence of a measurement rather than a measurement
  checker_verdict         what semantic.Checker actually returned at the
                          shipped thresholds. The report re-derives this from
                          similarity and gated for every row and refuses to
                          present its tables as the engine's if the two ever
                          disagree.
  signature_a/_b          the deciding fields read from each side, as
                          name=value|name=value
  remainder_a/_b          the free text left after the fields were removed
  latency_us              fastest of the timed repeats of one check, in
                          microseconds, with embeddings served from the local
                          cache
  detail                  the journaled explanation the comparator wrote
  note                    empty, or ERROR: ... for a row that could not be
                          measured. An ERROR row is retried on a resume.

WHAT NOT TO DO WITH IT
  Do not compute a precision or a false-positive rate over the rephrase-live
  rows. Every one of them is a duplicate by construction of the trial — the
  live run produced no negative class — so FP and TN are structurally zero and
  precision is 1.000 for every comparator. That corpus can measure detection
  and nothing else.

  Do not read the flight-213 rows for the itinerary extractor as a fair
  score. That extractor's vocabulary was written by reading that corpus. It is
  selection on the test set and cannot be undone by measuring more carefully.

  Do not average a rate across domains by averaging the rows: the corpora have
  different sizes. The report's per-domain tables have equal denominators
  (fifteen duplicates and fifteen negatives per domain) and are the ones to
  read.
